- **Q-008** [tag: knowhow] [difficulty: medium]
  - **Q:** What is the difference between `save()` and `update()` in pynamodb, and why does it matter?

- **Q-015** [tag: knowhow] [difficulty: medium]
  - **Q:** What is a GSI (Global Secondary Index), and why is it "eventually consistent"?
  - **A:** A GSI is a separate index with its own partition/sort key, allowing queries on non-primary-key attributes. It's eventually consistent because DynamoDB asynchronously replicates base table writes to the GSI — reads may lag 1–2 seconds.
  - **Source:** `docs/learn-this-project/01-knowhow-inventory.md#10-examples08-gsi-and-lsi`

- **Q-016** [tag: knowhow] [difficulty: medium]
  - **Q:** What is the difference between a GSI and an LSI?
  - **A:** A GSI has its own partition key (can query across partitions) and is eventually consistent. An LSI shares the base table's partition key (queries within one partition only) but supports strongly consistent reads. LSIs must be created at table creation time.
  - **Source:** `docs/learn-this-project/01-knowhow-inventory.md#10-examples08-gsi-and-lsi`

- **Q-020** [tag: knowhow] [difficulty: medium]
