## 3. Dependency-ordered commit plan

The publish skill materializes this into `tmp/publish-commit-plan.md` for the user, who runs the `git add` / `git commit` commands manually. The principle: **commit files in dependency order — least-dependent first — so the git history reads as a natural buildup**.

Aim for 15 commits minimum. The user can subdivide if they prefer more granular history. The last commit is always the hand-written `README.md`.

| # | Files | Suggested commit message | Rationale |

## 4. README co-write outline — English, sectioned

Total target: 250–500 words. The publish skill walks each section's questions one at a time and drafts ~50–120 words per section from the user's answers.

### § Title

- Format: `# <New Repo Name>` (e.g., `# John Doe DynamoDB POC`). Title-case.
- No tagline below — the first paragraph does that work.

### § Project description

- **Goal**: in ~80 words, tell a stranger what the project is and why it exists.
- **Question prompts**:
  1. "In one sentence, what is this project?"
  2. "Who cares about it? Who's it useful to?"
  3. "What's the simplest way to describe what it teaches or proves?"
- **Length target**: 60–100 words.

### § What's inside

- **Goal**: orient the reader to the structure so they know where to look.
- **Question prompts**:
  1. "What's the first thing a reader should open?"
  2. "If they only have time for one folder, which one do you want them to see?"
  3. "What's the climax — the most interesting part you built?"
- **Length target**: 50–80 words.

### § Install & run

- **Goal**: copy-pasteable steps from clone to running output.
- **Question prompts**:
  1. "What's the minimum command sequence from clone to first runnable example?"
  2. "What credentials or env vars does it need?"
- **Length target**: 40–80 words (mostly code block).

### § What I learned

- **Goal**: the *human* paragraph. The single most important section for a portfolio README.
- **Question prompts**:
  1. "What surprised you most while building this?"
  2. "If a friend asked 'what was the point?', what would you say?"
  3. "What was the hardest part?"
- **Length target**: 80–120 words.
- **Voice guardrails**: First-person past-tense. No "this tutorial" / "we learned" — use "I built" / "I worked through". The publish skill should refuse to write any phrase that sounds like a course report.

### § What's next (optional)

- **Goal**: shows the user has thought about gaps.
- **Question prompts**:
  1. "If you spent another month on this, what would you add?"
  2. "What's the one thing missing that bugs you most?"
- **Length target**: 30–60 words.

## 5. Hostile-scan rules (Audit mode)

Run each rule category against the repo. Group findings by severity. Be specific — name the exact file or line.

### File-pattern flags

| Pattern | Severity | Reason |
|---|---|---|
| `README-*.md` (any non-root README at root level) | 🔴 HIGH | Teaching-wrapper naming. |
| `*-tutorial.*`, `*-course.*` | 🔴 HIGH | Explicit teaching tags. |
| `docs/learn-*/` (any subdir) | 🔴 HIGH | Mentor's analysis docs. |
| `docs/tutorials/` | 🔴 HIGH | Course archive. |
| `.claude/skills/learn-this-project-{absorb,quiz,elevate,interview,demo,publish}/` | 🔴 HIGH | Sibling tutoring skills. Must not survive. |
| `.claude/skills/lesson-smith*/` | 🔴 HIGH | Course-authoring skills. |
| `TICKET.md`, `CLAUDE.md` | 🔴 HIGH | Cardinal teaching artifacts. |
| `chore.txt`, `notes.md`, `notes/`, `tmp/`, `scratch/` | 🟡 MEDIUM | Personal scratch; check before keeping. |
| `*.bak`, `*.orig`, `*.draft.md` | 🟡 MEDIUM | Draft files; usually delete. |
| `.idea/`, `__pycache__/`, `.venv/`, `*.egg-info/`, `.DS_Store` | 🔵 LOW | Hygiene; add to `.gitignore`. |

### README phrase flags (in any surviving `*.md`)

Severity 🔴 HIGH:
- `"this tutorial"`, `"in this project we"`, `"in this lesson"`, `"the goal of this lesson"`
- `"as a student"`, `"we learned"`, `"we'll learn"`, `"you'll learn"` (second-person teaching prose)
- `"course"`, `"the mentor"`, `"this curriculum"`
- First-person plural learning prose ("we built", "we set up") — usually a teaching-wrapper signature

Severity 🟡 MEDIUM:
- `"I learned a lot"` — filler; push for specifics in co-write
- `"basic"` in the project title or description — sounds like a tutorial level

### Commit-message phrase flags (`git log --all --format="%s%n%b"`)

Same phrase set as READMEs. Severity 🟡 MEDIUM (recoverable via rebase + reword; user must accept history rewrite).

Additionally:
- `"chore: ..."` / `"feat: ..."` / Conventional Commit prefixes — 🔵 LOW; matches a templated style. Not fatal but signals "scaffolded".

### Git ref flags (`git tag --list` + `git branch --all`)

Severity 🔴 HIGH:
- Tags named `tutorial-base`, `from-tutorial`, `v0-from-course`, `original`, `lesson-N`, `module-N`
- Branches named the same

### Residual directory flags

Severity 🔴 HIGH:
- Any `.claude/skills/learn-this-project-*/` directory **other than** `learn-this-project-meta/`.

### Suspicious-symmetry flags

Severity 🟡 MEDIUM (heuristic only):
- Multiple files with identical multi-line docstring shapes (3+ matching).
- Identical comment banners across multiple files (`# === Some Section ===` repeated verbatim).
- Numbered prefixes (`s01_`, `s02_`, …) — actually fine for this project (it's a deliberate naming convention and reads as personal style), but flag if combined with other symmetry signals.

### Hygiene flags

Severity 🔵 LOW:
- Missing `.gitignore` entries for `.venv/`, `__pycache__/`, `.DS_Store`.
- Committed `uv.lock` (this is actually correct — keep it; not a real flag).
- `dist/`, `build/`, `*.egg-info/` committed.
