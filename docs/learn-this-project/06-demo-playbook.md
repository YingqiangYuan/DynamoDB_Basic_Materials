# 06 — Demo Playbook

How to demo `dynamodb_basic_opeartions` effectively. Powers `/learn-this-project-demo`.

## Cardinal framing

This project's strongest demo signal is the **arc from minimal-poc to single-table M:N**. A viewer sees you start from a 5-line model definition and finish with a tradeoff matrix across three working M:N approaches. That's a learning *journey* on display, not just a code sample. The single most powerful beat is opening folder 11's `s02_gsi_inversion.py` next to `s01_adjacency_list.py` and walking the tradeoff — that moment tells a viewer "this person can hold multiple working designs in mind and pick".

## Wow features (1–3 strongest, in priority order)

1. **Folder 11 — three M:N approaches side by side.** `examples/11-single-table-many-to-many/s01_adjacency_list.py`, `s02_gsi_inversion.py`, `s03_composite_gsi.py`. Strongest because it's a real design decision shown three ways with their tradeoffs spelled out in the docstrings (write cost / read consistency / GSI count). Lands instantly with any interviewer who knows DynamoDB.
2. **Folder 10 — single-table 1:N with composite SK.** `examples/10-single-table-one-to-many/s01_setup_and_seed.py:20-21` (the `TX#<card_id>#<ts>` SK format) → `s03_query_card_transactions_by_date.py` (the range query that the SK format makes possible). The "the order of components in the SK *is* the access pattern" insight is a thing senior engineers nod at.
3. **Folder 09 — GSI cost comparison.** `examples/09-pipeline-metadata-demo/s04_compare_capacity.py` measures `ConsumedCapacity` for "FAILED runs via scan" vs "FAILED runs via StatusIndex GSI". Real numbers, not theory. Good for an audience that cares about cost.

## Recommended sequence — 5-minute version

For: tight time-boxed slot, hiring manager who wants to see "can they do the thing".

1. **Open `examples/README.md`** — say: "The whole curriculum is 12 folders, progressive." (10 sec, sets context.)
2. **Open `examples/00-minimal-poc/s01_minimal_poc.py`** — say: "This is the minimal pynamodb skeleton. Model + Meta + attributes + `use_boto_session`. Every other script is a variation on this shape." (30 sec.)
3. **Open `examples/10-single-table-one-to-many/models.py`** — say: "Here's where it gets interesting. One table, three entity types. The composite SK encodes card_id and timestamp." Then open `s01_setup_and_seed.py:20-21` to show the SK format. (90 sec.)
4. **Open `examples/11-single-table-many-to-many/s01_adjacency_list.py`** — read the top docstring out loud (it states the cost tradeoff explicitly). Open `s02_gsi_inversion.py` and contrast: "Same problem, half the writes, eventual consistency on the reverse." (90 sec.)
5. **Close** — "If I had three more months, the top priority would be a real test suite — `mise run test` is broken because `tests/` doesn't exist. Detailed roadmap is in `docs/learn-this-project/03-elevation-roadmap.md`." (15 sec — establishes that you've already thought about gaps.)

**Total ~5 minutes.** Practice once aloud; the timing self-corrects.

## Recommended sequence — 15-minute version

For: tech screen, peer engineer, or hiring manager with a DynamoDB background.

1. **Open `examples/README.md`** — narrate the 12-folder arc (1 min).
2. **`examples/00-minimal-poc/s01_minimal_poc.py`** — walk the script top-to-bottom. Highlight `use_boto_session` and explain it's not a pynamodb built-in (2 min).
3. **`examples/05-query-and-scan/s04_scan_and_filter.py`** — show the "scan + filter is billed on every row, not just matches" gotcha. Quote a number: "On a 1M-row table this is a 1M-RCU bill regardless of how many rows match" (2 min).
4. **`examples/06-condition-expression/s03_optimistic_lock.py`** — walk the manual version-counter retry loop. Mention that `VersionAttribute` exists and explain why doing it by hand is the right teaching choice here (2 min).
5. **`examples/09-pipeline-metadata-demo/models.py`** — show the `StatusIndex` GSI on `(run_status, start_ts)`. Walk why it exists: the main table's PK is `pipeline_name`, so "all FAILED runs across all pipelines" can't be a main-table query (2 min).
6. **`examples/10-single-table-one-to-many/`** — full walk of the composite-SK insight. `models.py` first (the wide nullable model), then `s01_setup_and_seed.py:20-21`, then `s03_query_card_transactions_by_date.py` (3 min).
7. **`examples/11-single-table-many-to-many/`** — open all three scripts in tabs, walk the tradeoff matrix. Land on the punchline: "M:N has no single right answer in DynamoDB — every approach trades writes vs. consistency vs. flexibility" (2 min).
8. **Close** — point at `docs/learn-this-project/03-elevation-roadmap.md` and the 3 highest-leverage gaps (tests, DynamoDB Local toggle, CI) (1 min).

**Total ~15 minutes.** This is the version to rehearse for any DynamoDB-related role.

## Audience tailoring matrix

| Audience | Recommended |
|---|---|
| Hiring manager, role *related* to DynamoDB / AWS / database design | 15-min sequence above. Emphasize beats 5–7. They'll ask follow-ups during the demo; that's good, follow their context. |
| Hiring manager, role *unrelated* (e.g., frontend, ML research) | **Strongly consider not demoing this project at all** — DynamoDB modeling doesn't transfer signal to those roles. If you must, do the 5-min version and frame as "an example of how I systematically learn an unfamiliar tool". A more relevant project will signal much better. |
| Peer engineer (already knows DynamoDB) | 15-min sequence, but **skip beats 2 and 3** (basics they already know). Go straight to folder 09 → 10 → 11. Use the time saved for deeper discussion of the M:N tradeoffs. |
| Non-technical stakeholder | Skip this project. The substance is implementation detail. Show them something user-facing. |

## Do NOT show — explicit list

**The cardinal rule: do not be detected as a teaching project.** If the audience can tell this came from a tutorial, the demo's value flips from positive to negative.

The following must NOT appear on screen during any demo:

- `README.md` (top-level) — reads as a course/learning guide. The top has phrases like "Setup" and "Learning order" that signal teaching.
- `README-cn.md` — Chinese-language teaching wrapper. Same issue, in another language.
- `TICKET.md` — explicit "learning task card". Highest tell of all.
- `CLAUDE.md` — AI-assistant configuration. Signals "I let an AI guide me through this".
- `docs/learn-this-project/` (entire directory) — this very file plus its 6 siblings. The mentor's analysis docs.
- `.claude/skills/learn-this-project-{absorb,quiz,elevate,interview,demo,publish}/` — the six sibling skills. Their `description` fields explicitly mention "interactive walkthrough", "quiz me", etc.

The right path: before demoing, **publish a sanitized copy of the repo to your own GitHub** with these artifacts deleted. The `/learn-this-project-publish` skill walks that transform. Then demo *that* repo, not the original.

**Allowed exceptions:**

- `.claude/skills/learn-this-project-meta/` — keep this one. It's a meta-skill the user genuinely built/learned and is an acceptable portfolio bonus per the README's "Show Your Work" convention.

### Project-specific borderline items

- `README.rst` — package-metadata RST file. Boring, technical, fine to show, but probably not interesting to a viewer. Skip unless asked.
- `dynamodb_basic_opeartions/tests/helper.py` — exists but contains no actual tests. If a viewer opens `tests/`, the emptiness is a tell. Acknowledge it head-on: "no test suite yet; here's the roadmap" — turn it into the closing beat.
- `mise.toml` task list (especially `mise run test`, which is broken) — if a viewer types `mise tasks ls` you can let them; the broken-test entry is a *good* segue to your "next priority" closing line. Don't hide it.
- `examples/cleanup_all_tables.py` — fine to show as a utility. Doesn't signal teaching.

## Recovery moves

| If this happens during the demo | Say |
|---|---|
| `python examples/<x>.py` errors with `NoCredentialsError` | "Let me check my `.env` — moment." Open `.env.example`. Recover. If can't fix in 30s, switch to a read-only walkthrough of the source. |
| AWS DynamoDB returns `ProvisionedThroughputExceededException` | "DynamoDB just throttled me — the demo table's been busy. Let me walk through what *would* have happened." Switch to source walkthrough. |
| `create_table(wait=True)` hangs 30s | Use it: "Watch — this is the table activation wait. It's exactly why the script's lifecycle reuses the table across runs." Turns dead air into content. |
| Viewer asks a question you don't know | "Good question — let me check the source." Open the file. Reading aloud while you find the answer is fine. If you genuinely don't know, say "I'd need to verify that — I don't want to guess." |
| You realize you've opened a `do-NOT-show` file (e.g., `README-cn.md`) | Close it immediately. Do not narrate the slip. Continue. |
| Folder 11's three scripts produce identical-looking output | This is real — the queries return similar shapes. Explicitly call out: "The output looks the same, but watch the table count in the AWS console — three different tables, three different schemas." |

## Rehearsal questions (skill drills the user on these)

1. "Why pynamodb and not raw boto3?" — Test: does the user say "DynamoDB-JSON marshalling" or just "higher-level"?
2. "What's the difference between `Model.save()` and `Model.update()`?" — Test: does the user mention that `save()` overwrites the whole row?
3. "Walk me through what the composite SK `TX#<card_id>#<ts>` lets you query that a simple `<ts>` SK wouldn't." — Test: does the user explain that component order *is* the access pattern?
4. "Why does folder 11 have three different table names?" — Test: does the user explain that each script uses a different schema and they couldn't coexist on one table?
5. "What would you build next?" — Test: does the user name a real gap (tests / DynamoDB Local / CI) rather than something invented on the spot?

## Closing line (steal this)

> "If I'd had three more months, I'd have written a real test suite first — `mise run test` doesn't work today because `tests/` doesn't exist, but the harness is already configured. Once tests exist, CI follows. After that, a DynamoDB Local toggle so anyone can run the curriculum offline. The full roadmap is documented; I treat 'what's missing' as part of the deliverable."

Lands two things at once: you know what's broken, and you've already thought about how to fix it.
