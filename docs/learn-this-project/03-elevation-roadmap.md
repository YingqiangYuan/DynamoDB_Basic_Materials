# 03 — Elevation Roadmap

What 3–6 more months of senior-engineer investment would do to this repo. Powers the `/learn-this-project-elevate` skill.

## Executive view

In priority order:

1. **Add a real test suite** — `mise run test` is currently broken (no `tests/` directory). Every other improvement compounds once tests exist.
2. **Lower the local-dev friction by toggling DynamoDB Local** — running the curriculum currently costs real (small) money and requires AWS credentials. A `USE_DYNAMODB_LOCAL=1` toggle would let learners go zero-cost and offline.
3. **Wire up CI** — there is no `.github/workflows/` directory at all. Once tests exist, a GitHub Actions job that runs them on each push would catch dep drift instantly.
4. **Type-safe single-table keys** — examples 10 and 11 hand-roll `f"CUSTOMER#{customer_id}"` strings; a tiny `KeyBuilder` would prevent silent format drift between scripts.
5. **Systematic capacity logging** — only one script (`09/s04_compare_capacity.py`) measures `ConsumedCapacity`; a small decorator could surface it everywhere and turn the curriculum into a cost-literacy lesson.

## Upgrade areas

### Test depth and coverage (highest leverage)

- **Current state.** No tests. The `tests/` directory referenced in `mise.toml:40` (`mise run test`) and `:45` (`mise run cov`) does not exist. The path `dynamodb_basic_opeartions/tests/helper.py` exists but contains only a wrapper around an external coverage helper, no actual test functions. `pytest` and `pytest-cov` are installed via the `test` extra in `pyproject.toml:43-45` but never invoked successfully.
- **Senior-engineer target state.** A `tests/` directory at the repo root with:
  - `tests/conftest.py` providing a `dynamodb_local` fixture that starts the `amazon/dynamodb-local:latest` Docker container, points pynamodb at `http://localhost:8000` (via `Meta.host`), and tears down after the session.
  - One test file per example folder (e.g., `tests/test_03_crud_basic.py`) that imports the script's functions (after refactoring scripts into `def main():` shapes) and asserts on the side-effects.
  - A golden-output layer for the cost-comparison demo: store the expected `ConsumedCapacity` ratios in `tests/golden/09_capacity.json` and fail the test if they drift.
  - `mise run test` should pass on every commit.
- **Alternatives considered.**
  - **DynamoDB Local (Docker) + pytest fixtures.** ✅ Closest to real API behavior, accurate type marshalling, ~500ms session-scoped startup. Requires Docker on the dev machine and in CI.
  - **`moto` (in-process mocking).** Fast (no Docker), but mocks the API surface and may diverge on edge cases (especially GSI eventual consistency, which is silently strong in `moto`). Good for unit tests of wrapper code; weak for testing the lessons themselves.
  - **Subprocess against real AWS in CI.** Works, but burns money on every PR and ties CI to a credential. Reject for this project.
- **Knowledge prerequisites.**
  - `pytest` fixtures, scopes (`session` vs `function`), parametrize.
  - Docker basics: pulling an image, port mapping, healthchecks.
  - pynamodb's `Meta.host` attribute override (this is the only knob needed to retarget at DynamoDB Local).
  - GitHub Actions service containers (so the same fixture works in CI).
- **Suggested learning path.**
  1. `pytest` fixtures and `conftest.py` — the official pytest docs section on fixtures.
  2. Spin up `docker run -p 8000:8000 amazon/dynamodb-local` locally and verify with `aws dynamodb list-tables --endpoint-url http://localhost:8000`.
  3. Wire pynamodb to it — set `Meta.host = "http://localhost:8000"` on a copy of the Card model and run `s01_minimal_poc.py`'s logic.
  4. Convert one example into a test (`tests/test_00_minimal_poc.py`) and run it both locally and via `mise run test`.

### Developer experience — lower AWS friction

- **Current state.** Setup requires (a) an AWS account, (b) a profile in `~/.aws/credentials`, (c) `AWS_PROFILE=<profile>` in `.env`, (d) IAM permission to `dynamodb:*` on `dynamodb_basic_opeartions_*`. First-time learners often stall on one of (b)/(c)/(d). Every full run of the curriculum makes 100+ DynamoDB API calls; not free, just cheap.
- **Senior-engineer target state.** A `DYNAMODB_ENDPOINT` env var (read in `dynamodb_basic_opeartions/one/one_02_config.py`, which is currently empty). When set, `OneBotoSesMixin.dynamodb_client` is overridden to point at the local endpoint. A `scripts/dev-up.sh` brings up DynamoDB Local in Docker and exports the env var. Learners can choose: real AWS (production-like, costs pennies) or local (offline, free, identical lesson content).
- **Alternatives considered.**
  - **Env-var toggle + Docker (proposed above).** Minimal code change, no new deps. Cleanest.
  - **VS Code devcontainer.** Pre-baked Python + Docker + DynamoDB Local + mise. Great for Codespaces; heavy for learners who don't use VS Code.
  - **LocalStack.** Full AWS emulation. Overkill — this project doesn't touch SQS, IAM, S3, etc. Adds a multi-GB image to the dev loop.
- **Knowledge prerequisites.**
  - `os.environ.get(..., default)` and how pynamodb's `Meta.host` attribute changes the endpoint.
  - Docker basics (same as test depth section).
  - Optionally, devcontainer JSON schema if you go that route.
- **Suggested learning path.**
  1. Set `Meta.host` on a single model and watch boto3 routing change.
  2. Externalize the override into `one_02_config.py`.
  3. Write the bash script. Test that the curriculum is fully runnable with no AWS account configured.

### API / contract design — single-table keys

- **Current state.** Examples 10 and 11 build PK/SK as ad-hoc strings: `examples/10-single-table-one-to-many/s01_setup_and_seed.py:20-21` defines `tx_sk(card_id, ts) -> f"TX#{card_id}#{ts.isoformat()}"` inline; `examples/11-single-table-many-to-many/s01_adjacency_list.py:70-71` writes `pk=f"CUSTOMER#{customer}"` directly. There's no shared key constructor or validator — a typo in one script silently breaks the queries in another.
- **Senior-engineer target state.** A small `examples/_keys.py` (or a real module if it lives in the package) containing:
  - One `dataclass` or `NamedTuple` per entity type (CustomerKey, CardKey, TransactionKey, EdgeKey, …).
  - Each with `to_pk()` and `to_sk()` methods.
  - A `parse(pk, sk) -> Union[...]` for the read side (lets the caller branch on entity type without inspecting the discriminator string).
- **Alternatives considered.**
  - **Static methods on a `KeyBuilder` class.** Explicit, testable, zero deps. ✅ Right size for a teaching repo.
  - **`@dataclass` per entity + `__str__` for serialization.** More Pythonic, slightly higher ceremony.
  - **Port `dynamodb-toolbox` (JS) or use the in-development `pynamodb-attributes`.** Powerful but is a large dep + ecosystem dependency for a teaching POC.
  - **Status quo (inline strings).** Fine until two scripts disagree on a separator. Silently broken queries are hard to teach against.
- **Knowledge prerequisites.**
  - `@dataclass(frozen=True)` and why frozen helps when keys are dict-ish.
  - Type annotations: `Literal["CUSTOMER", "CARD", ...]` for discriminators.
  - Pattern: the "tagged union" / discriminated union pattern.
- **Suggested learning path.**
  1. Refactor `tx_sk` into a `TransactionKey` dataclass; rerun `s01_setup_and_seed.py` to confirm output unchanged.
  2. Add `TransactionKey.parse(pk, sk) -> "TransactionKey"` and use it in `s03_query_card_transactions_by_date.py`.
  3. Generalize to all entity types in folder 10.

### Observability and cost monitoring

- **Current state.** Only `examples/09-pipeline-metadata-demo/s04_compare_capacity.py` reads `ConsumedCapacity`. The other 30+ scripts don't surface cost at all. A learner finishes the curriculum without ever seeing how much each operation cost.
- **Senior-engineer target state.** A `CapacityTracker` context manager in `examples/_common.py`:
  ```python
  with CapacityTracker("s01_query_basic"):
      for card in Card.query(...): ...
  # On exit, prints: "s01_query_basic: 3 RCU, 0 WCU, est $0.0000004"
  ```
  Wrapped around the "real work" section of every script. Bonus: write totals to a CSV so a `cost_summary.py` can aggregate the curriculum's full cost.
- **Alternatives considered.**
  - **Decorator / context manager (proposed).** Local, opt-in, zero infra. ✅
  - **CloudWatch dashboard.** Authoritative, but requires CW permissions and only shows table-level numbers (not per-script).
  - **Add `return_consumed_capacity='TOTAL'` to every call by hand.** Verbose; clutters the lesson.
- **Knowledge prerequisites.**
  - pynamodb's `return_consumed_capacity` kwarg and its response structure.
  - DynamoDB pricing model: 1 RCU = 4 KB strongly-consistent read; 1 WCU = 1 KB write; transactional ops are 2×.
  - Python decorators / context managers.
- **Suggested learning path.**
  1. Add a `return_consumed_capacity='TOTAL'` to one call in `s04_scan_and_filter.py`; print the response field.
  2. Wrap it in a `with` block.
  3. Promote to `examples/_common.py` and apply to two more scripts.

  - Sets up Python 3.12 via `actions/setup-python`.
  - Starts DynamoDB Local as a service container.

  - Uploads coverage to Codecov (only if the repo is public).

  - **No CI, manual smoke runs.** Fine for now; bad once anyone else contributes.
- **Knowledge prerequisites.**
  - GitHub Actions YAML structure (jobs, steps, services).

  - Codecov upload action (if going public).
- **Suggested learning path.**

### Code organization

- **Current state.** Every example script is top-level procedural — no `if __name__ == "__main__":` guard (except `cleanup_all_tables.py` at line 29). Side-effects fire on import. This is fine for "run a script and watch output", and bad for "import a script into a test".
- **Senior-engineer target state.** Wrap each script's logic in a `def main():` and gate the entrypoint with `if __name__ == "__main__": main()`. Optionally extract shared helpers (`PREFIX`, table-wipe loop) into `examples/_common.py`.
- **Alternatives considered.**
  - **`def main()` + guard (proposed).** Minimal diff, big payoff for testability. ✅
  - **Convert to pytest test functions directly.** Lower ceremony but loses the "I can just `python file.py` to play with it" affordance, which is the whole point of the format.
  - **Click/typer CLI wrapper.** Pretty, but adds a dep and ceremony that obscures the lesson.
- **Knowledge prerequisites.**
  - Python's `__name__` mechanic.
  - Test isolation: why side-effects-on-import is a problem for `pytest --collect-only`.
- **Suggested learning path.**
  1. Wrap one script (`00-minimal-poc/s01_minimal_poc.py`) in `def main()` and verify `python file.py` still works.
  2. Write `tests/test_minimal_poc.py` that imports and asserts.
  3. Roll out to the other folders one at a time.

## Projects-not-included (hypotheses with evidence)

- **DynamoDB Streams + Lambda example.** No mention anywhere in code or `examples/README.md`. The AxiomCard domain (`PipelineRun`, `Transaction`) is a natural fit for stream-driven audit logs. Likely deliberately scoped out — Streams require IAM + Lambda + CloudWatch and would dwarf the lesson.
- **DynamoDB Local toggle.** Discussed above as the highest-leverage DX improvement but not currently implemented; the empty `one_02_config.py` is the right place for it.
- **A `VersionAttribute`-based optimistic-lock example.** Folder `06/s03_optimistic_lock.py` deliberately hand-rolls version counters to expose the mechanism. A natural follow-up script could replace it with pynamodb's built-in `VersionAttribute` to show the convenience layer. Not in the repo today.
- **PartiQL examples.** Zero mentions. Probably scoped out because pynamodb's first-class API is the focus.
- **A `time-to-live` (TTL) example.** Not in the curriculum. Easy add: another folder showing `Meta.ttl` and the resulting delete behavior.
- **Async / `aiobotocore`.** No `async def` anywhere. Probably deliberately scoped out — pynamodb's sync API is the lesson surface.
- **Multi-region / Global Tables.** All Meta.region values are `"us-east-1"`. Multi-region is operational, not a data-modeling lesson.

None of these are gaps that hurt the project's stated mission. They're material the curriculum would grow into if it ran longer.
