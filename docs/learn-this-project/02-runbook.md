## Prerequisites

| Tool | Version | Install command |
|---|---|---|
| **Python** | 3.12 | Managed by `mise` — `mise install python@3.12` |
| **mise** | latest | `curl https://mise.run \| sh` (see [mise docs](https://mise.jdx.dev/getting-started.html)) |
| **uv** | latest | Managed by `mise` — installed automatically |
| **AWS CLI** | v2 | `brew install awscli` (macOS) or see [AWS docs](https://docs.aws.amazon.com/cli/latest/userguide/install-cliv2.html) |
| **AWS account** | — | An AWS account with DynamoDB access in `us-east-1` |

Verify Python version: `mise ls python --current` (should show 3.12.x).

## First-time setup

1. **Clone the repo** (if not already):
   ```bash
   git clone <repo-url>
   cd learn_dynamodb_basic_opeartions-project
   ```

2. **Set up your AWS profile** — create a `.env` file from the template:
   ```bash
   cp .env.example .env
   # Edit .env and set AWS_PROFILE=<your-profile-name>
   ```

3. **Install all dependencies**:
   ```bash
   mise run inst
   ```
   This creates `.venv/` and installs all packages from `pyproject.toml` via `uv`.

4. **Verify AWS access**:
   ```bash
   aws sts get-caller-identity --profile <your-profile-name>
   ```
   Should return your account ID and ARN.

## Running the examples

Each example script is a standalone Python file. Run them directly:

```bash
python examples/00-minimal-poc/s01_minimal_poc.py
```

**Folder independence:**
- Folders **00–08**: Independent. Run any script in any order.
- Folders **09–11**: Sequential within each folder. Run `s01` → `s02` → `s03` → ... in order.

**Suggested learning path:**
1. `00` → `02`: Basics (model, attributes, table management)
2. `03` → `05`: CRUD and reading data (save, get, update, query, scan)
3. `06` → `08`: Correctness and performance (conditions, transactions, indexes)
4. `09`: Real-world composite demo (pipeline metadata)
5. `10` → `11`: Capstone — single-table design (1:N and M:N)

**Cleanup after learning:**
```bash
python examples/cleanup_all_tables.py
```
This lists and deletes all `dynamodb_basic_opeartions_*` tables (with confirmation).

## Common failures and fixes

| Symptom | Likely cause | Fix |
|---|---|---|
| `NoCredentialError` / `ProfileNotFound` | `.env` not set or `AWS_PROFILE` points at a missing profile | Check `.env` exists and the named profile is in `~/.aws/credentials` |
| `ResourceNotFoundException` on query/get | Table doesn't exist yet | Run the corresponding `s01_*` script first to create the table |
| `Table already exists` error | Table from a previous run still exists | This is expected — scripts are idempotent; they handle this with `if not exists` |
| `ConditionalCheckFailedException` | Condition expression failed (expected in folder 06) | Read the script comments — these are intentional demonstration failures |
| Slow `create_table` (5–30s) | DynamoDB table creation latency | Normal. Tables are kept alive between runs to avoid this wait. |
| `ModuleNotFoundError: dynamodb_basic_opeartions` | Dependencies not installed or wrong venv | Run `mise run inst` and ensure you're using the project's `.venv` |

## Where to look when something breaks

- **AWS Console**: DynamoDB → Tables → filter by `dynamodb_basic_opeartions_` prefix. Check Items tab for actual data.
- **Script output**: All examples print their results to stdout. Errors include the full DynamoDB error message.
- **pynamodb source**: When a pynamodb operation behaves unexpectedly, check pynamodb's [documentation](https://pynamodb.readthedocs.io/) or source for the exact API semantics.
- **CloudWatch**: If running against a real AWS account, DynamoDB metrics (consumed capacity, throttling) are in CloudWatch under the DynamoDB namespace.
- **`.env` file**: First place to check for credential/region issues.
