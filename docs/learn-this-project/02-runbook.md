# 02 — Runbook

Copy-pasteable instructions to install, run, and verify `dynamodb_basic_opeartions`. The `/learn-this-project-absorb` skill walks the user through this verbatim.

## Prerequisites

| Tool | Version | Install |
|---|---|---|
| **mise** | latest | `curl https://mise.run \| sh` (see https://mise.jdx.dev) |
| **Python** | 3.12 (pinned in `mise.toml`) | `mise install python` |
| **uv** | latest (pinned in `mise.toml`) | `mise install uv` |
| **claude** | latest (pinned in `mise.toml`, optional unless using the `/learn-this-project-*` skills) | `mise install claude` |
| **pandoc** | 3.9 (pinned in `mise.toml`, only needed by `notebook-to-markdown`) | `mise install pandoc` |
| **AWS account** | any | Console at https://aws.amazon.com. Configure a profile with `aws configure --profile <name>`. The IAM principal needs `dynamodb:*` on tables matching `dynamodb_basic_opeartions_*` in `us-east-1`. |

`mise install` (run with no arguments from the repo root) installs every pinned tool at once.

## First-time setup

```bash
# 1. Clone and enter
git clone <repo-url>
cd dynamodb_basic_opeartions-project

# 2. Install mise-managed tools (Python 3.12, uv, claude, pandoc)
mise install

# 3. Set up AWS credentials
cp .env.example .env
# Edit .env and set AWS_PROFILE=<your-profile-name>
# mise.toml loads .env automatically (see line 3: _.file = ".env")

# 4. Create virtualenv and install all Python deps
mise run inst       # alias for: uv venv --allow-existing && uv sync --all-extras

# 5. Smoke-test that AWS access works end-to-end
python examples/00-minimal-poc/s01_minimal_poc.py
# Expected: creates table "dynamodb_basic_opeartions_cards", writes one row,
# reads it back, prints holder_name=Alice / credit_limit=10000.
```

If step 5 hangs for more than 30 seconds it's usually `Card.create_table(wait=True)` waiting for AWS to transition the table to ACTIVE — normal on a brand-new table. After the first run, the script reuses the table and finishes in ~2 seconds.

If step 5 errors with `KeyError: 'AWS_PROFILE'`, the `.env` file isn't being loaded. Confirm `mise.toml` line 3 reads `_.file = ".env"` and that you're running the command via `mise run` (or that `mise` has activated the env via its shell hook).

## Running locally

There is no long-running server. The "app" is the curriculum — each example is a standalone script that you run once, watch the output, and move on.

### Suggested order (from `examples/README.md`)

1. `00-minimal-poc/s01_minimal_poc.py` — verify AWS connectivity.
2. `01-attributes/s01..s03` → `02-table-management/s01..s03` — internalize the pynamodb skeleton.
3. `03-crud-basic/s01..s05` → `04-batch-operations/s01..s03` → `05-query-and-scan/s01..s04` — everyday operations.
4. `06-condition-expression/s01..s03` → `07-transactions/s01..s03` → `08-gsi-and-lsi/s01..s04` — correctness and indexes.
5. `09-pipeline-metadata-demo/s01..s04` (in order) — first composite demo.
6. `10-single-table-one-to-many/s01..s03` (in order) → `11-single-table-many-to-many/s01..s03` — single-table design.

Each script prints its own output to stdout. Watching it run **is** the learning experience.

### When you're done for the day

```bash
python examples/cleanup_all_tables.py
```

This lists every table whose name starts with `dynamodb_basic_opeartions`, prints the list, and deletes them after a `y/N` prompt. Run it whenever you don't want the tables sitting in your account incurring (small) storage charges.

## Tests

**There is no test suite.** `mise run test` and `mise run cov` reference a `tests/` directory that does not exist — they will fail with `ERROR: file or directory not found: tests`. The `dynamodb_basic_opeartions/tests/` subpath inside the package contains only a `helper.py` with no actual test functions.

The examples themselves are the validation: if a script runs end-to-end and prints sensible output, the underlying pynamodb code path works. See `03-elevation-roadmap.md` § Test depth for what a real test suite would look like.

## Common failures and fixes

| Symptom | Likely cause | Fix |
|---|---|---|
| `KeyError: 'AWS_PROFILE'` at first DynamoDB call | `.env` not loaded, or `AWS_PROFILE` not set in it | `cp .env.example .env`, edit, retry. Run via `mise run` to ensure env loading. |
| `botocore.exceptions.NoCredentialsError` | profile name in `.env` doesn't match any local AWS profile | `cat ~/.aws/credentials` to confirm; fix `.env` |
| `AccessDeniedException` on `CreateTable` / `Scan` | IAM principal lacks DynamoDB permissions | Attach `AmazonDynamoDBFullAccess` (or a tighter equivalent scoped to `arn:aws:dynamodb:us-east-1:*:table/dynamodb_basic_opeartions_*`) |
| Script hangs ~5–30s at `create_table(wait=True)` | First run on a fresh table | Normal — DynamoDB transitions to ACTIVE. Subsequent runs skip this branch. |
| `botocore.exceptions.EndpointConnectionError` | Wrong region or no internet | Region is hardcoded `us-east-1` in `dynamodb_basic_opeartions/one/one_03_boto_ses.py:19`. Verify network. |
| `mise run test` fails with "tests not found" | The `tests/` dir doesn't exist | See note in **Tests** above. Skip the test tasks. |
| Multiple stale tables in AWS console | Forgot to clean up | `python examples/cleanup_all_tables.py` |
| Folder 11's three scripts seem to "all work" but on the same table | They actually each use a **different** table name (see inventory § folder 11). | This is intentional — no fix needed. |
